# Phase 3 OAuth Identity Implementation Plan

> **For agentic workers:** follow the pinned Superpowers TDD process; preserve red/green evidence. Work only on `phase/03-oauth-identity` and do not alter Phase 2's PR.

**Goal:** OAuth-protected MCP service with separate browser-authenticated staff identities, no live ClickUp data.

**Architecture:** Cloudflare OAuthProvider 1.x handles MCP-side OAuth. GitHub upstream OAuth verifies human identities and a server-side numeric allowlist binds these to MCP grants. Every `/mcp` call validates token, scope and active staff status before an isolated SDK tool handler.

**Tech Stack:** existing MCP TypeScript SDK v2 / TypeScript 6 / Vitest / Wrangler, plus pinned `@cloudflare/workers-oauth-provider@1.2.3`.

**Spec:** `docs/superpowers/specs/2026-10-10-phase3-auth-design.md`.

## Global constraints

No ClickUp operations. No model API keys. No generated/fake lockfile. No public OAuth bypass. At most four staff; unknown IDs fail closed. OAuth provider token issuance is upstream responsibility.

## Review focus

1. Token audience/resource mismatches, scope downgrade, request header spoofing.
2. Browser state/cookie tampering, repeat callbacks/consent, client identity and redirect mixup.
3. GitHub user ID spoofing, network timeout or malformed responses, revoked account access.
4. Four simultaneous accounts leaking session data or shared mutable principal.
5. Incomplete host configuration unexpectedly falling back to unauthenticated mode.
