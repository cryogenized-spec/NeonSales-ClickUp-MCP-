# Phase 2 — MCP SDK foundation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use Superpowers executing-plans or subagent-driven-development, test-by-test. Do not skip/redact red CI or falsify local dependency resolution.

**Goal:** Establish an SDK-v2-backed, modular, type-safe, adversarially tested MCP foundation, while rejecting all unauthenticated public requests.

**Architecture:** `src/mcp/create-server.ts` uses official MCP SDK v2 and Zod; `src/mcp/handler.ts` exposes SDK protocol only for in-process tests; `src/index.ts` is fail-closed Cloudflare Worker entrypoint. Four users require future OAuth identities per request, never a global shared session.

**Tech Stack:** Node 22, TypeScript 6.0.2, npm exact lockfile, MCP server/client SDK 2.3.1, Zod 4, ESLint 10 + typescript-eslint 8.56, Prettier 3.9, Vitest 5, Wrangler 4.x.

**Spec:** `docs/superpowers/specs/2026-10-10-phase2-sdk-design.md`

## Global constraints

No ClickUp credentials, Cloudflare deployment or AI-provider model API. Two–four human users later connect their own subscription accounts; Phase 2 proves only protocol and public denial. Prefer current official MCP 2026-07-28, not v1 hand-built JSON-RPC. No handcrafted npm lockfiles.

## Review focus

1. Public `/mcp` accidentally reachable via diagnostic, query, spoofed authorization or alternate HTTP method → always deny.
2. Four parallel forged-user requests share mutable identity or permit leakage → deny all, deterministic responses.
3. Invalid schema/method handled by hand-written parser instead of official MCP SDK → use SDK instance and internal protocol tests.
4. CI green while tests skipped/no-op scripts or lockfile absent → fail.
5. Runtime Worker bundle accidentally embeds test-only token or ClickUp secret → reject build review, logs and scans.
